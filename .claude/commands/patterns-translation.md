# Patterns Translation Sync

`apps/docs/src/pages/preview/patterns/{category}/{id}/` のパターンプレビューを英語に翻訳し、同期します。

日本語（`index.astro`）を正として、英語（`en.astro`）を同期先とします。
`apps/docs/src/config/patterns.ts` の `description.en`（カテゴリと各アイテム）も同期対象です。

`en.astro` は `/en/patterns/...` ページでソースコードとしてそのまま表示されるため、コメントも含めて英語読者向けの完成品として扱います。

`preview/page-layouts/` は英語版を持たず `index.astro` を共用するため対象外です。


## 対象範囲

- `$ARGUMENTS` でカテゴリが指定されている場合はそのカテゴリのみ対象とする
- 未指定の場合は `preview/patterns/` 配下の全カテゴリを対象とする


## 作業手順

### 1. ファイル一覧の取得と分類

各パターンディレクトリの `index.astro` と `en.astro` の有無を Glob で取得し、以下の3カテゴリに分類する：

| カテゴリ | 条件 | アクション |
| --- | --- | --- |
| **新規** | `index.astro` があるが `en.astro` がない | テキスト部分を英訳して `en.astro` を作成 |
| **更新候補** | `index.astro` と `en.astro` の両方がある | サブエージェントに渡し、差分があれば更新 |
| **孤立** | `en.astro` があるが `index.astro` がない | 削除対象として報告 |

更新候補の差分判定はコマンド側では行わない。メインエージェントが全ファイルを読むとコンテキストを圧迫するため、担当サブエージェントが `index.astro` と `en.astro` を読み比べ、差分がなければ「スキップ」として報告する。
差分の概要を把握済みの場合は、その概要をサブエージェントに渡す。


### 2. 分類結果の報告

分類結果をユーザーに報告し、実行の承認を得る。

```
## パターン翻訳同期プラン

### 新規作成（{n}件）
- {category}/{id}/

### 更新候補（{n}件）
- {category}/{id}/

### 削除（{n}件）
- {category}/{id}/en.astro（対応する index.astro なし）

実行してよろしいですか？
```


### 3. 翻訳の実行

承認後、以下を実行する：

#### 3a. 孤立ファイルの削除

対応する `index.astro` がない `en.astro` を削除する。

#### 3b. 翻訳サブエージェントの起動

新規・更新対象のパターンをカテゴリ単位でまとめ、1グループあたり10件前後になるよう分けて `lism-docs-translator` サブエージェントを並列起動する。`feature/` や `section/` のような大きいカテゴリは単独または分割し、数件しかないカテゴリは隣接カテゴリと統合する。

各サブエージェントに伝える情報：
- 担当パターンの一覧（カテゴリ/ID）と対象ファイルパス
- 各パターンが「新規作成」か「更新候補」か
- 差分の概要が分かっている場合はその内容
- 後述の「パターン翻訳の個別ルール」の全文（プロンプトに含めて渡す）

#### 3c. patterns.ts の description 同期

`apps/docs/src/config/patterns.ts` はコマンド側（メインエージェント）で更新する：
- 新規カテゴリ・新規パターンは `description.en` を追加する
- `description.ja` が変更されていれば `description.en` も更新する


### 4. 最終チェック（コマンド側で実施）

このセクションはサブエージェントには渡さない。全サブエージェントの完了後、`en.astro` に日本語文字（漢字・ひらがな・カタカナ）が残っていないことをリポジトリルートで確認する：

```bash
rg -n '[一-龥ぁ-んァ-ヶー々]' apps/docs/src/pages/preview/patterns --glob 'en.astro'
```

コメントも英訳対象のため、コメント行を除外せずチェックする。
残っていれば該当ファイルの担当サブエージェントに差し戻し、出力がゼロ件になってから完了報告する。


### 5. 結果の報告

各サブエージェントの結果をまとめて報告する。

```
## パターン翻訳同期結果

### 新規作成（{n}件）
- {category}/{id}/en.astro

### 更新（{n}件）
- {category}/{id}/en.astro — {変更概要}

### 削除（{n}件）
- {category}/{id}/en.astro — 削除済み

### スキップ（{n}件）

### patterns.ts
- 追加 {n}件 / 更新 {n}件

### 最終チェック
- 日本語残留: なし / {n}件を差し戻して解消
```


## パターン翻訳の個別ルール（サブエージェントへ渡す）

対象は MDX ではなく `.astro` のため、エージェント定義の「MDX の翻訳ルール」（frontmatter・サイト内リンクの `/en/` 化・import パス調整・DummyText）は適用しない。「最優先: 意味の正確性」「翻訳の品質基準」「用語対応表」「避けるべき直訳パターン」の共通基準には従う。

### 基本方針

- コンポーネント構造・import・props・CSS クラス名は `index.astro` と同じにする（翻訳で変えない）
- `import './_style.css'` はそのまま維持する（`_style.css` は両言語で共有）
- `DemoLayout` の `title` prop、URL、`alt=""` のような空の alt はそのまま維持する
- テキスト部分（見出し・本文・ボタンラベル等）のみ英訳する
- コメント（`{/* ... */}`）も英訳する。`en.astro` はソースコードとして表示され、コピペして使う読者向けの説明になるため

### 更新候補の場合

1. `index.astro` と `en.astro` を両方読み、以下の観点で差分を判定する
   - コンポーネント・import の追加・削除・変更
   - props の変更（レスポンシブ値・スタイル props）
   - 日本語テキスト・コメントの変更
2. 差分がなければファイルを変更せず「スキップ」として報告する。英訳の文言だけが異なる場合（日本語側が変わっていない場合）は更新不要
3. 差分がある箇所だけを `index.astro` に揃え、変わっていない箇所の既存英文はそのまま維持する

### テキストの翻訳方針

- 直訳ではなく、英語として自然な表現を使う
- ダミーテキストは英語の自然なダミーテキストに置き換える

### 日本語固有表現の英語化

**`en.astro` に日本語文字（漢字・ひらがな・カタカナ）を残さない。** 以下を必ず英語に変換すること：

- **人名**: ローマ字にし、名→姓の順にする（例: 佐藤 美咲 → Misaki Sato）
- **日付**: 「2020年1月1日」→ "January 1, 2020" のように英語の日付形式にする
- **肩書き・役職**: 「代表取締役社長」→ "CEO"、「部長」→ "Director" など英語の一般的な役職名にする
- **住所**: 英語のダミー住所に置き換える
- **電話番号**: そのまま維持してよい
