# Translation Sync

`apps/docs/src/content/ja/` の MDX を正として `apps/docs/src/content/en/` へ翻訳同期する。
翻訳ルールは `lism-docs-translator` サブエージェント（`.claude/agents/lism-docs-translator.md`）に集約されている。コマンド側で再掲しない。


## 対象範囲

- `$ARGUMENTS` でファイル・ディレクトリ指定あり: その範囲のみ
- `root`: `ja/` 直下の mdx のみ（サブディレクトリ除外）
- 未指定: `ja/` 配下の全 `.mdx`
- `_demo/` は常に除外する（`en/` から `../ja/_demo/` を import して共用）


## 作業手順

### 1. ファイル一覧の取得と分類

`ja/` と `en/` の MDX 一覧を Glob で取得し、3つに分類する。

| 分類 | 条件 | アクション |
| --- | --- | --- |
| 新規 | `ja/` にのみある | 翻訳して `en/` に作成 |
| 更新候補 | 両方にある | サブエージェントに渡し、差分があれば更新 |
| 孤立 | `en/` にのみある | 削除対象として報告 |

更新候補の差分判定はコマンド側で行わない（メインが全ファイルを読むとコンテキストを圧迫する）。担当サブエージェントが読み比べ、差分がなければ「スキップ」として報告する。差分の概要が分かっている場合（`docs-update` のフェーズ1直後など）はサブエージェントに渡す。

### 2. 分類結果の報告

分類結果を報告し、実行の承認を得る。

```
## 翻訳同期プラン

### 新規作成（{n}件）
- ja/path/to/file.mdx

### 更新候補（{n}件）
- ja/path/to/file.mdx

### 削除（{n}件）
- en/path/to/file.mdx（対応する ja/ ファイルなし）

実行してよろしいですか？
```

### 3. 翻訳の実行

承認後に行う。

1. 孤立ファイル（`en/` にのみあるもの）を削除する
2. 新規・更新候補を `.claude/commands/docs-update.md` の「対象ファイルの分類とグルーピング」表と同じグループに分け、`lism-docs-translator` を並列起動する。3件以下のグループは隣接グループと統合し、多いグループは分割してよい。各サブエージェントに渡すもの:
   - 担当ファイルパス一覧（`ja/` 基準）
   - 各ファイルが「新規作成」か「更新候補」か
   - 差分の概要（分かる場合）

### 4. 検証（コマンド側で実施）

全サブエージェント完了後、報告の前に行う。

1. 日本語残留チェック。リポジトリルートで実行する:

   ```bash
   rg -n '[一-龥ぁ-んァ-ヶー々]' apps/docs/src/content/en --glob '*.mdx'
   ```

   `<DummyText lang="ja"` の残留も確認する。フォント見本のように `ja/` 側でも同じ位置に表示用の日本語を置いている箇所だけ例外とし、それ以外は担当サブエージェントに差し戻す。
2. ビルド確認。`runner` サブエージェントで `nr build:docs` を実行し、MDX が壊れていないことを確認する。`nr dev:docs` 起動中はビルドせず、その旨を報告する（dev 側のコンテンツストアが壊れる）。失敗時はエラーの要点を報告し、修正せずユーザーの判断を仰ぐ。

### 5. 結果の報告

サブエージェントの結果をまとめて報告する。

```
## 翻訳同期結果

### 新規作成（{n}件）
- en/path/to/file.mdx — {英語タイトル}

### 更新（{n}件）
- en/path/to/file.mdx — {変更概要}

### 削除（{n}件）
- en/path/to/file.mdx — 削除済み

### スキップ（{n}件）
- en/path/to/file.mdx — 差分なし

### 検証
- 日本語残留: なし / {n}件を差し戻して解消
- ビルド: 成功 / 失敗（要点） / 未実施（理由）
```

あわせて、サブエージェントがセルフチェックで修正した問題の件数と、ガイドライン外の判断があればその旨を伝える。
