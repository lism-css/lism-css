# KvEditor

トップページのヒーローとライブコードエディターを連動させるコンポーネントです。この文書には、現在の動作の契約、コードだけでは判断しにくい設計理由、複数ファイルにまたがる制約を残します。

色、寸法、レイアウト、DOM構造、関数ごとの処理は実装を正本とし、ここには転記しません。

## 現在の位置づけ

`KvEditor.astro`の`DEMO_MODE`は`live`です。シナリオに沿った編集を自動再生し、利用者が操作を始めたら通常のエディターとして明け渡します。

`ai`モードの実装も残していますが、Lism自体にAIアシスタント機能はありません。製品機能だと誤解されるため現在は無効です。チャット形式の見せ方が必要になった場合に再利用するため、`player.ts`とシナリオ文言を保持しています。

## 動作の契約

### 手動編集

- HTMLとJSXは同じ内容の別表記です。どちらのタブで編集しても、変換できた内容をヒーローへ反映します。
- HTMLはブラウザーと同じく寛容に描画し、タグの閉じ忘れなどは警告だけを出します。JSXは変換できない間、最後に変換できたHTMLをヒーローへ残します。
- 入力上限は2,000文字です。超過分を切り捨てず、入力前の値と選択範囲へ戻します。IME変換中は確定後に判定します。
- 入力が止まってから構文を確認します。初期コードと異なる間は、構文警告とは別に`Restore initial code`を表示します。
- Tabは2スペースのインデント、Shift+Tabはアウトデントです。複数行選択では行単位で処理します。

### ライブループ

- 各シナリオ結果を順に再生し、最後は初期コードへ戻す編集で次の周回へつなぎます。周回ごとにHTMLとJSXを交互に表示します。
- コード領域へのマウスホバー、画面外、非表示タブでは一時停止し、条件が戻れば続きから再開します。
- エディターへのフォーカス、ポインター操作、入力、停止ボタンでは完全停止します。自動では再開しません。
- 停止後にコードが変わっていなければ再生位置から続けます。変更されていれば、利用者の編集を途中状態として上書きしないよう、初期コードへ戻して最初から再生します。
- 自動再生はページのスクロール位置を動かしません。

## 設計判断

### HTMLを唯一のモデルにする

ヒーローの正本はHTML文字列1つです。HTMLタブ、JSXタブ、自動再生が別々の状態を持つと、片方の更新漏れによる同期ずれが起きるためです。

各タブの入力中テキストは別に保持し、必要になるまで再生成しません。これは、タブを切り替えていないのに利用者の改行や整形を変えないためです。JSXの編集中に変換できない状態になっても、最後に変換できたHTMLをヒーローへ残します。閉じタグなどを入力している途中でプレビュー全体が消えることを避けています。

`convert.ts`は汎用のJSXコンパイラーではなく、このデモに必要なLism表記だけを扱います。対応外の式を推測したり評価したりせず、変換失敗として扱う方が、入力を壊さず安全です。Lismのpropとトークンの判定には`lism-css/config`のデータだけを使い、Reactをクライアントバンドルへ持ち込みません。

### HTML・JSX変換の範囲

保守時に変換対象を広げすぎないため、主な対応範囲を示します。

| HTML | JSX |
| --- | --- |
| `-p:10`などのProperty Class | `p="10"`などのLism prop |
| BPクラスとCSS変数の組 | `p={[20, 40, 50]}`形式の配列prop |
| `-bd`などの値なしクラス | `bd`などのboolean prop |
| `l--box`など、クラスだけで往復できるレイアウト | `<Box>`などのレイアウトコンポーネント |
| `u--*`、`set--*`、`-hov:*` | `util`、`set`、`hov` prop |

通常のHTML属性と変換対象外のクラスは、失わずにそのまま保持します。一方、任意の`{}`式、レスポンシブのオブジェクト記法、変数参照、未知の大文字コンポーネントは扱いません。レイアウトコンポーネントも、クラスだけでは固有propを復元できないものは対象外です。

レスポンシブpropは配列記法だけを対象にし、HTMLへ展開して元のクラスとCSS変数を再現できる場合だけ集約します。見た目が似ている値を推測して変換すると往復で入力が変わるため、再現できない表記は通常のクラスと`style`として保持します。

### 初期コードを1か所から配る

`initial-code.ts`は、ヒーローのSSR、エディターの初期値、ハイライト済みの初期表示、復元先の共通ソースです。別々に持つと、JSの起動前後や復元時に表示が変わるためです。

初期コードと各シナリオ結果は、`convert.ts`の出力と同じ正準形を保つ必要があります。HTMLとJSXの往復で文字列が変わると、JSX側の編集や再生で意図しない差分が入り、タブ切り替え後の表示も崩れます。この制約は`convert.test.ts`で検証しています。

日本語版と英語版は、文言とURL以外の構造・クラスを揃えます。`scenario.ts`の編集定義を全言語で共有するためです。シナリオの置換対象は言語に依存しないクラス属性に限定し、各時点で1回だけ一致する文字列にします。

### シナリオは差分から累積結果を作る

各ステップは直前のコードへの小さな置換として定義し、再生先となるHTML全文を初期コードから順に導出します。ステップごとの全文を手で複製すると、初期コードの変更を一部へ反映し忘れるためです。

置換対象が0回または複数回一致した場合は、モジュール初期化時に失敗させます。誤った場所を静かに書き換えるより、開発中に不整合へ気づけることを優先しています。

### 初期表示はSSRし、編集機能を後から足す

ヒーローと最初のハイライト済みコードはビルド時に生成します。JavaScriptの読み込み前でも見出しをHTMLへ含め、初期表示の色が途中で変わらないようにするためです。

ブラウザー側のShikiは、必要な言語・テーマ・JavaScript正規表現エンジンだけを直接依存として持ち、アイドル時に読み込みます。Astroが内部で使うShikiはアプリ向けの公開APIではなく、間接依存へ頼るとAstro側の変更で壊れるためです。初期表示はSSR済みなので、クライアント用のハイライターを初回描画へ含める必要もありません。

### 入力と表示を別レイヤーにする

実際の入力にはネイティブの`textarea`を使い、Shikiの出力は表示専用レイヤーにします。IME、選択、Undo、キーボード操作、読み上げを自作せずブラウザーへ任せながら、構文ハイライトを表示するためです。

2つのレイヤーは同じスクロール要素にせず、`textarea`だけをスクロールさせて表示レイヤーを`transform`で追従させます。別々のスクロール位置を同期すると、内容の差し替えやスクロール可能量の違いでずれるためです。

### キーボード操作で閉じ込めない

HTML・JSXタブはARIAのタブパターンに従い、左右矢印、Home、Endで切り替えます。

Tabによるインデントは、ポインターで編集を始めた場合か、フォーカス後に文字入力を始めた場合だけ有効にします。キーボードで通過しただけならTabを奪わず、編集中もEscの直後はTabまたはShift+Tabで外へ移動できます。コード編集の便利さより、キーボードトラップを作らないことを優先しています。

無限ループの途中経過はスクリーンリーダーのライブリージョンへ流しません。エディターへフォーカスすれば再生が止まり、常設の再生・停止ボタンでも制御できます。

### 自動再生も実際の編集経路を使う

デモは動画ではなく、通常のエディターAPIへシナリオを流し込みます。利用者が途中で操作を引き継げることと、デモの結果が実際の編集結果と一致することを優先しています。

タイピング中の不完全なコードは表示レイヤーだけへ反映し、変更単位が確定してからヒーローへ反映します。クラス名やJSXの閉じタグを書いている途中の壊れたレイアウトを見せないためです。

自動再生は、画面外や非表示タブでは一時停止します。フォーカス、ポインター操作、入力があれば完全停止し、利用者へ操作権を渡します。`prefers-reduced-motion`では自動開始せず、明示的に再生された場合もタイピング演出を省きます。

### 検索モーダルはヒーローから委譲する

ヒーローは編集のたびに`innerHTML`を差し替えるため、生成された検索ボタンへ直接付いたイベントは失われます。lism-uiのモーダルトリガーは初期化時の要素へ直接バインドされるので、ヒーローコンテナでクリックを受け、常設されているヘッダーの検索ボタンへ委譲します。

このため、ヒーローの再描画後に検索ボタンへ個別のリスナーを付け直す実装にはしません。再描画経路が増えたときの付け忘れを避けるためです。

### サニタイズはself-XSSだけを対象にする

現在の入力は保存も共有もされず、入力者と閲覧者が同じです。そのため`sanitize.ts`はself-XSSを前提に、スクリプト実行へつながる要素・属性・URLだけを除去します。初期SSRはリポジトリ内の信頼済みコードなので対象外です。

入力の保存、URL共有、他人の入力の表示を追加する場合、この前提は成立しません。その変更では既存処理を流用せず、脅威モデルとサニタイザーを先に見直してください。

## 変更時の確認

自動テストは次を対象にしています。

- 初期コードと全シナリオ結果のHTML・JSX往復
- シナリオ置換の一意性と累積結果
- 変換、差分、HTML検証、ライブループの主要ロジック

```bash
nr test --filter=lism-docs
```

DOMをまたぐ挙動は自動テストだけでは確認できません。関連箇所を変えたときだけ、日本語・英語トップページでタブ切り替え、手動編集への引き継ぎ、停止と再開、初期コードへの復元、キーボードでのエディター脱出、検索モーダル、`prefers-reduced-motion`を確認します。
