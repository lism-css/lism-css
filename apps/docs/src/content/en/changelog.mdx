## lism-css v0.27.0 (2026.09.04)

This release contains **breaking changes**.

### Split `lh` from `hl` and redefined it as a real line-height prop (#583)

- `lh` used to be a compatibility alias of `hl`. It is now an independent prop / token that manages the actual `line-height` as a unitless ratio. The tokens are `xs: 1.25` / `s: 1.5` / `m: 1.75` / `l: 2` / `xl: 2.25` (unlike `hl`, it has no default on `body`, so the middle key is `m` rather than `base`).
- Values are emitted through the `--lh` variable and resolved as `line-height: var(--lh, calc(1em + var(--hl) * 2))`. Since `--lh` is inherited, descendants also get line spacing recalculated from their own `font-size`.
- To migrate: replace token usages such as `lh="s"` that were adjusting half-leading with `hl="s"`. `lh="1"` still gives no extra leading (`line-height: 1`).
- `u--trim` / `u--trimAll` now trim by `calc((1em - 1lh) / 2)`, so trimming works correctly whether line spacing is managed by `hl` or `lh`.

### `--s-unit` / `--hl-unit` are now fixed rem values (#581)

- Changed `--s-unit` (≈8px) and `--hl-unit` (≈2px) from `calc()` expressions tied to `--fz--base` to the fixed values `0.5rem` / `0.125rem`. Changing `--fz--base` no longer changes the base units for spacing and leading. A recipe for keeping them tied to the font size as before has been added to the Typography tokens page.
- Added an `xl` token (5 × `--hl-unit`) to `hl`.

### New `bdrs` token scale (#579)

- Changed to a scale whose increments grow arithmetically (a second-order arithmetic progression) and added `50`: `10: 0.25rem` / `20: 0.375rem` / `30: 0.625rem` / `40: 1rem` / `50: 1.5rem` (`99` is unchanged). `20`–`40` are smaller than before, so bump the key up one step to keep the previous look.
- Added a `+1px` correction to the computed `--bdrs--inner` in `.set--bdrsInner`.

### Two-layer box-shadow (#591)

- The `bxsh` tokens (`10`–`50`) are now two layers: a small near-side shadow on top of the previous one. Added the near-side size `--shsz--5` and color `--shc--near`, and changed the default `--shadow` color to `hsl(220 2% 4% / 8%)`.

### Narrowed the properties targeted by `has--transition` (#584)

- The default `--transitionProps` changed from `all` to visual properties only (`color`, `background-color`, `border-color`, `box-shadow`, `scale`, `rotate`, `translate`, `transform`, `opacity`, `filter`, `backdrop-filter`). This prevents unintended animations on load or layout changes.
- `hasTransition` now also accepts a string such as `'color, opacity'` to specify the target properties directly.

### Stronger override resistance in the no_layer build (#585)

- In the `no_layer` build, Property Classes are now always `!important` and `u--` Utility Class selectors are doubled, making them harder to override from external CSS. The output of the regular `@layer` build is unchanged.

### Other

- Added an `xs` (`-0.05em`) token to `lts`.
- Moved the `border-width` / `border-color` of `-bd` out of the layers so they are not overridden by `border` shorthands in higher layers (#589).
- Fixed `Center` overflowing horizontally when it contains a long `pre` (#597).
- Adjusted the default mix ratio of `-hov:-bgc` from 25% to 20%.

### `@lism-css/ui` v0.27.0 (2026.09.04)

Requires `lism-css` v0.27.0 or later.

**Added Tooltip and Popover (#588)**

- Added `Tooltip` and `Popover`, positioned with CSS Anchor Positioning. Unsupported browsers get a CSS fallback.
- Tooltip: visibility is handled entirely in CSS; the only JS closes it on the Esc key. Position it with `side` (`top` / `bottom` / `start` / `end`) and `align` on `Popup`.
- Popover: uses the native Popover API, so no client-side JS is needed. Composed of `Root` / `Trigger` / `Popup` / `Close`.
- Tuning CSS variables (`--tooltip-offset` / `--tooltip-duration` / `--tooltip-delay` / `--tooltip-delay--close`, `--popover-offset` / `--popover-duration`) are received on `Root`.
- A speech-bubble arrow is shown by default. Change its size with `--tooltip-arrow` / `--popover-arrow`, or set `0` to hide it.

**Avatar initials placeholder (#587)**

- When `src` is omitted, the first character of the `name` prop is shown as an initial. The root gets a `b--avatar--initial` modifier, where you can override the background color and so on.
- When neither `name` nor `alt` is given, the placeholder is treated as decorative (`aria-hidden`).

**Modal (#596)**

- Clicking an in-page link (`#id`) inside a Modal now closes it without blocking the navigation. Clicks with modifier keys, links targeting another tab, and clicks whose default was prevented by another handler are excluded.

## lism-css v0.26.0 (2026.08.16)

### Added the `lism-block` layer (#546, #559)

- Added a `lism-block` layer for base parts whose base styles are managed in CSS (`b--`). It is empty in the core; `@lism-css/ui` and user-defined classes are placed there.
- The layer order is now `lism-base → lism-block → lism-trait → lism-primitive → lism-custom → lism-utility`. Placing `lism-block` right after `lism-base` (a weaker position) means classes you add explicitly (`is--`, `has--`, `l--`, etc.) always win over a `b--` base style.
- The `lism-component` layer is kept in the declaration for backward compatibility (removing it would move any `@layer lism-component` in existing user CSS to the end and change its behavior).

### Unified custom class naming into two categories (#546)

- Custom classes are now organized into just two categories: `b--` (Block Class) and `c--` (Custom Class).
- Renamed `c--` from Component Class to Custom Class (a free-form custom class matching the `lism-custom` layer, with no granularity restriction).
- Removed the `p--` / `z--` conventions.

### Other

- Updated dependencies for security fixes.

### `@lism-css/ui` v0.26.0 (2026.08.16)

This release contains **breaking changes**. It requires `lism-css` v0.26.0 or later.

**Migrated to `b--` classes and the `lism-block` layer (#559)**

- Renamed every component class from `c--{name}` to `b--{name}`, and moved their CSS from `@layer lism-component` to `@layer lism-block`. The element (`_element`) and modifier (`--modifier`) conventions are unchanged.
- To migrate: replace `.c--{name}` with `.b--{name}` in your CSS and markup. Move any CSS that overrides these components into `@layer lism-block`, or into `@layer lism-custom` if you need it to win over `b--`.

**Moved base styles into CSS (#559)**

- Base styles that used to be emitted as Lism Props (Property Classes) are now CSS, so you can override them from your own CSS. The following defaults changed as a result.
- Badge: the default border radius is now a pill shape (`--bdrs--99`).
- Tabs: `variant="line"` is now a standard style, and the default `variant` is `'default'`. The previous default decoration has been separated into `.b--tabs--default`.
- Avatar: the default size is now managed in CSS as `--w: 2em`.
- Button / Accordion.Root / Details / NavMenu: no longer emit `l--flex` / `l--stack` by default. Pass the `layout` prop (e.g. `layout="flex"`) if you need that layout.
- Details: removed `flow="s"` from Content, so the default spacing between child elements is now `--flow--base`. To keep the previous spacing, set `.b--details_content { --flow--base: var(--flow--s) }`.

**Accessibility improvements for Tabs and Modal (#559, #563)**

- Tabs: added roving tabindex and arrow / Home / End key navigation. Panels now use the `hidden` attribute instead of `aria-hidden`, and tabs get `type="button"` and an `id` that panels reference via `aria-labelledby`. The `?lism-tab=` deep link now works in the React version too.
- Tabs: fixed tabs becoming unusable when `defaultIndex` was out of range.
- Modal: `Modal.OpenBtn` / `Modal.CloseBtn` now get `type="button"` by default, and `Modal.OpenBtn` gets `aria-haspopup="dialog"` (both overridable via props).
- Modal: open/close animations are now disabled under `prefers-reduced-motion: reduce`.
- Modal: fixed the modal closing unintentionally when a drag started inside it and ended on the backdrop.
- Modal: `data-is-open` is now removed and `scrollbar-gutter` restored even for closes that bypass `closeDialog()`, such as submitting a `<form method="dialog">`.
- Modal: dropped support for non-`dialog` elements in `setEvent`, since focus trapping and backdrop inerting rely on the native `dialog` element.

**Removed the Chat component (#564)**

- Chat has been removed from the package. No markup changes are needed — copy the CSS shown on the example page in the docs (including its `@layer lism-block` wrapper) into your project to reproduce the same appearance.

- **v0.8.x**: Switched to managing line-height via half-leading. Reorganized layout modules (`WithSide` → `SideMain`, extracted `FluidCols`, added `SwitchCols`). Removed the dynamic modules (accordion / modal / tabs) and migrated them to `@lism-css/ui`. Renamed many tokens (e.g., `--c--main` → `--brand`, `--c--line` → `--divider`)
