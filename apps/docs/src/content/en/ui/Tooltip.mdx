Showing and hiding the tooltip is handled entirely with CSS. JavaScript only handles closing it with <kbd>Esc</kbd>.

- It appears on hover over `<Tooltip.Root>`, or on keyboard focus (`:focus-visible`) of `<Tooltip.Trigger>`.
- Moving the pointer onto the popup does not hide it.
- Pressing <kbd>Esc</kbd> hides it. Moving the pointer or focus away and back shows it again. (This state is tracked via the `data-dismissed` attribute on `<Tooltip.Root>`.)

:::note
Placing `<Tooltip.Trigger>` and `<Tooltip.Popup>` as siblings inside `<Tooltip.Root>` automatically links them via `aria-describedby` and `id`.

- Place `<Tooltip.Popup>` as a sibling *after* `<Tooltip.Trigger>`. The focus-visible display is controlled with a sibling selector, so reversing the order prevents the tooltip from appearing.
- Don't place interactive elements like links or buttons inside a tooltip. If you need interactive content, use [Popover](/en/ui/Popover) instead.
- Touch devices don't trigger hover, so the tooltip can't be reliably shown. **Don't put critical information only inside a tooltip.**
- `<Tooltip.Trigger>` must be a focusable element. If you use something other than the default `button` (e.g. `as="span"`), add `tabindex="0"`.
:::

## Usage

Provided as `Tooltip` from the `@lism-css/ui` package.


### Import

<ImportPackage component="Tooltip" script="tooltip.js" packageName="@lism-css/ui" css="style.css" />

`<Tooltip.Root>`, `<Tooltip.Trigger>`, and `<Tooltip.Popup>` are available.


### Props

| Prop | Description |
|---|---|
|<PropBadge>`<Tooltip.Root>`</PropBadge><br/>`tooltipId`|Specifies the ID used for `<Tooltip.Trigger>`'s `aria-describedby` and `<Tooltip.Popup>`'s `id`. If omitted, an automatically generated ID is used.|
|<PropBadge>`<Tooltip.Root>`</PropBadge><br/>`delay`|Specifies the delay before the popup appears. Output as the `--tooltip-delay` variable.|
|<PropBadge>`<Tooltip.Trigger>`</PropBadge><br/>`tooltipId`|Output as the value of `aria-describedby`. Only specify this when using the component standalone, outside `<Tooltip.Root>`.|
|<PropBadge>`<Tooltip.Popup>`</PropBadge><br/>`id`|Output as the `id` attribute. Only specify this when using the component standalone, outside `<Tooltip.Root>`.|
|<PropBadge>`<Tooltip.Popup>`</PropBadge><br/>`side`|Specifies the side the popup appears on. Output as the `data-side` attribute. Accepts `top` / `bottom` / `left` / `right` / `start` / `end`, where `start` / `end` are the logical counterparts of `left` / `right` that follow the writing direction. Default: `top`.|
|<PropBadge>`<Tooltip.Popup>`</PropBadge><br/>`align`|Specifies the alignment along the axis perpendicular to `side`. Output as the `data-align` attribute. Accepts `start` / `center` / `end`. Default: `center`.|
|<PropBadge>`<Tooltip.Popup>`</PropBadge><br/>`offset`|Specifies the gap between the trigger and the popup. Output as the `--tooltip-offset` variable.|

:::warning
Don't set individual IDs on `<Tooltip.Trigger>` or `<Tooltip.Popup>` when they're inside `<Tooltip.Root>`. If you need to set an explicit ID, use only the `tooltipId` prop on `<Tooltip.Root>`.

The child-level `tooltipId` / `id` props exist for placing the parts apart from each other without `<Tooltip.Root>` (passing the same ID to each part yourself). Setting them on only some children inside `<Tooltip.Root>` breaks the linkage.
:::


### CSS variables

Use the following CSS variables to adjust the appearance.

| Variable | Default | Description |
|---|---|---|
|`--tooltip-offset`|`var(--s5)`|The gap between the trigger and the popup.|
|`--tooltip-delay`|`0.4s`|The delay before the popup appears.|
|`--tooltip-delay-out`|`0.15s`|The grace period before the popup hides. Keeps the popup visible while the pointer moves from the trigger to the popup.|
|`--tooltip-duration`|`0.15s`|The duration of the fade transition. Set to `0s` when `prefers-reduced-motion: reduce` is set.|

Override the color, spacing, border radius, and shadow using Lism properties (`bgc`, `c`, `p`, `bdrs`, `bxsh`, etc.). By default, the tooltip uses an inverted color scheme with `--text` as the background and `--base` as the text color.

:::note
`left` / `right` refer to physical screen directions. `start` / `end` are logical directions that follow the writing direction, so they swap sides when `dir="rtl"` is set.

Regardless of which side you choose, the popup automatically flips to the opposite side if it doesn't fit within the viewport.

The flip is evaluated against the popup's containing block. If an ancestor has `container-type` (Lism's `is--container`), `transform`, `contain`, or similar, that element's edges are used instead of the viewport. When that element is small, the popup may appear on the opposite side from the one you specified.
:::

## Browser support

Tooltip positioning uses [CSS Anchor Positioning](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_anchor_positioning).

In browsers without support (e.g. Firefox ESR 140), it falls back to absolute positioning relative to `<Tooltip.Root>` (the element that wraps the trigger). In this case, the automatic flip when the popup doesn't fit within the viewport doesn't happen, so the tooltip may get clipped. The `offset` (`--tooltip-offset`) gap also isn't applied.
