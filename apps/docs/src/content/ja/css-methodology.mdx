## デザイントークン

タイポグラフィ、余白、カラー、シャドウなど、主要なプロパティに対して段階的なプリセット値やセマンティックなキーワードでCSSカスタムプロパティを定義しています。

トークンを流用することでデザインに**一貫性**が生まれ、使用しているプロパティの**意図**も読み取りやすくなります。また、あとからサイト全体を微調整する必要が出てきてもトークンの値を変更するだけでよくなり、**メンテナンス性**も高まります。


詳しくは[トークン解説ページ](/docs/tokens/)を参照してください。

## CSSのクラス設計

Lism CSS の中心的なクラス群について、その設計思想を説明します。

### Set Class

`lism-base` 層の中で定義される、HTML 要素の基礎スタイリングや変数セットを行うためのユーティリティクラスを **Set Class** として定義しています。

|分類|形式|例|
|---|---|---|
|Set Class|`set--{style}`|`set--plain`,<br />`set--hov`,<br />`set--bxsh`|

### Primitive Class

レイアウトを組み立てるための小さな積み木として **Primitive Class** を定義しています。

さらにその中で、いくつかの種類に分類しています。

|分類|形式|例|
|---|---|---|
|Layout Primitives<br /><small>レイアウトの構成単位となる Primitive</small>|`l--{name}`|`l--grid`,<br />`l--columns`|
|Atomic Primitives<br /><small>レイアウトの最小単位となる Primitive</small>|`a--{name}`|`a--divider`,<br />`a--icon`|

Primitive クラスはバリエーションや子要素クラスを持たない、単体で機能するクラスです。BEM 構造を持つのは、後述の [Block Class](#block-class)（`b--`）と [Custom Class](#custom-class)（`c--`）のみです。

また、Primitive 同士の併用は以下のルールに従ってください。

| 組み合わせ | 可否 | 備考 |
|---|---|---|
| `l--` × `l--` | NG | 同カテゴリの併用は不可 |
| `a--` × `a--` | NG | 同カテゴリの併用は不可 |
| `l--` × `a--` | 非推奨 | 役割的には同居しない想定 |

### Trait Class

要素に「役割」を宣言したり、「機能」を付与するためのクラスを **Trait Class** として定義しています。

|分類|形式|例|
|---|---|---|
|`is--` Trait<br /><small>要素に役割（〜である）を宣言する</small>|`is--{name}`|`is--container`,<br />`is--wrapper`,<br />`is--layer`,<br />`is--boxLink`|
|`has--` Trait<br /><small>要素に機能（〜を持つ）を付与する</small>|`has--{name}`|`has--transition`,<br />`has--gutter`,<br />`has--snap`|

`is--` と `has--` の判定軸は次の通りです。

|  | `is--` | `has--` |
|---|---|---|
| 意味 | 〜である（役割・存在の宣言） | 〜を持つ（機能の付与） |
| CSS 変数 | 必須ではない | 必須（カスタマイズポイントを提供） |

詳しい使い分けや判断軸については [命名規則](/docs/naming/) ページも参照してください。


### Block Class

`b--` プレフィックスで定義する **Block Class** は、サイト共通で繰り返し使う基礎部品（ボタン・バッジ・カード級）のためのクラスです。  
「ベーススタイルはCSS側にある」ことを名前で保証するクラスで、ベーススタイルは `@layer lism-block` に定義してCSSファイル側で管理します。コアの `lism-css` は専用レイヤーを用意するだけで、クラス自体はユーザーが定義します。

```css
@layer lism-block {
  .b--btn { /* ... */ }
}
```

`b--` は、次の3つをすべて満たす部品にだけ使ってください。

1. サイト内の複数ページ・複数箇所で繰り返し使う共通部品である
2. クラス1つでベーススタイルがほぼ定まる状態にしたい部品である（スタイルの修正をCSSファイル側だけで完結させたい）
3. 粒度がボタン・バッジ・カード級の自己完結した部品である（ページセクション全体やサイト骨格は対象外）

満たさない部品は `c--` にします。CSSを書かずに、何のパーツかを示す名前付けとしてだけ使っても構いません（後述の[「独自クラスの分類」](#独自クラスの分類)を参照）。

`b--` クラスは BEM 構造（Block / Modifier / Element）を持つことができ、それぞれ次のような形式で定義します。

|分類|形式|例|
|---|---|---|
|Block<br /><small>本体クラス</small>|`b--{name}`|`b--btn`,<br />`b--card`|
|Modifier<br /><small>バリエーション</small>|`b--{name}--{modifier}`|`b--btn--outline`|
|Element<br /><small>子要素</small>|`b--{name}_{element}`|`b--card_header`,<br />`b--card_body`|

:::point
Modifier は `.b--btn.b--btn--outline` のように Block クラスと併記して使います。  
Element は `_`（アンダースコア）一つ区切りです。
:::

Blockの併用（`.b--xxx.b--yyy`）は基本 NG ですが、次の組み合わせは許容されます。

- Block と Modifier の併用: `.b--xxx.b--xxx--variant`
- Block と 他の Block の Element の併用: `.b--xxx.b--yyy_elem`

:::point
`b--` に Property Class を併用しても構いません。Property Class はレイヤーの外にあり `b--` より必ず強いため、例外的な調整やブレークポイントの切り替え（`-p_sm` 等）にはむしろ Property Class の使用をおすすめします。  
逆に `lism-block` は `lism-primitive` より強いレイヤーなので、`b--` の要素に `l--` や Trait クラスを付けても、`b--` 側ですでに指定しているプロパティは上書きできません。レイアウトのバリエーションが必要な場合は、Modifier クラスをCSS側に定義するか、Property Class で上書きしてください。
:::



### Utility Class

装飾・機能として用途が明確なユーティリティクラスを次のように定義しています。

|分類|形式|例|
|---|---|---|
|Utility Class|`u--{style}`|`u--cbox`,<br/>`u--trim`|



### Property Class

Lism CSS では、単一のCSSプロパティに対応するユーティリティクラスを **Property Class** として定義しています。

主要なプロパティに対して、よく使われる値や専用のトークン値に合わせたユーティリティクラスを定義しており、レスポンシブ対応できるようになっています。


Prop クラス には以下の3種類の形式があります。

|形式|説明|例|
|---|---|---|
|<WhsNw>`-{prop}:{value}`</WhsNw>| 各プロパティごとの主要な値やトークンの値を利用するためのユーティリティクラス |<WhsNw>`-fz:l`</WhsNw>,<br/><WhsNw>`-d:none`</WhsNw>|
|`-{prop}`| 変数 `--{prop}` を受け取るためのクラス |`-p`,<br/>`-fz`|
|`-{prop}_{bp}`| 変数 `--{prop}_{bp}` を受け取るためのクラス |<WhsNw>`-p_sm`</WhsNw>,<br/>`-p_md`|


:::warning
\* 全てのCSSプロパティに対応するクラスがデフォルトで用意されているわけではありません。  
\* ブレークポイント対応クラスも、さらにその中で主要な一部のプロパティのみ標準でサポートされています。
:::



詳しくは[Property Class 一覧ページ](/docs/property-class)を参照してください。

## 独自クラスの命名と定義場所

その他、Lism CSS の各クラス分類（`set--`, `is--`, `has--`, `l--`, `a--`, `u--`, `-{prop}:{value}`）に合致する独自クラスを追加する場合は、同じプレフィックスを用いてそれぞれの定義レイヤーに追加するようにしてください。

なお、Lism の既存クラスを上書きしたい場合は、該当するレイヤー内で行ってください。

例えば、`set--` クラスの再定義は `@layer lism-base` で行います。この時、lismの`main.css`よりあとで読み込むスタイルで定義するか、`.set--xxx.set--xxx` のように同じクラス名を続けることで優先度をあげるなどして上書きすること。

```css
@layer lism-base {
  /* 新規追加 */
  .set--hoge { /* ... */ }

  /* 上書き */
  .set--plain.set--plain { /* ... */ }
}
```


### 独自クラスの分類

Lism CSS が提供するクラス群のどれにも当てはまらない、ユーザーが自分で定義するクラスは、次の2分類で整理してください。

|分類|命名|スタイルの書き方|
|---|---|---|
|サイト共通で繰り返し使う基礎部品<br /><small>ボタン・バッジ・カード級</small>|`b--{name}`<br /><small>例: `b--btn`</small>|ベーススタイルを `@layer lism-block` に定義し、CSS側で管理します。（→ [Block Class](#block-class)）|
|それ以外のカスタムクラス全般<br /><small>コンポーネント・ゾーニング・ページ固有要素など粒度不問</small>|`c--{name}`<br /><small>例: `c--card`,<br />`c--siteHeader`</small>|Property Class を中心に組み立てます。CSSを書かずに、何のパーツかを示す名前付けとしてだけ使っても構いません。CSSを書く場合は `@layer lism-custom` に定義します。（→ [Custom Class](#custom-class)）|

`b--` にできるのは、[Block Class](#block-class) の3条件（サイト共通の繰り返し利用・ベーススタイルのCSS管理・ボタン/バッジ/カード級の粒度）をすべて満たす部品だけで、それ以外はすべて `c--` です。「ベーススタイルはCSS側にある」ことを名前で保証するのが `b--` で、`c--` にはそうした約束はありません。サイト骨格やページ固有要素は、CSSを書く場合でも `c--` のままにします。迷ったときは `c--` から始めて、3条件を満たす部品としてCSS管理へ切り替えたくなった時点で `b--` へリネームして昇格させてください。

なお、プレフィックスなしの自由命名も引き続き使えます（後述の[「プレフィックスなしのクラスで守ること」](#プレフィックスなしのクラスで守ること)を参照）。Lismらしく揃えるなら `c--` をおすすめします。

```css
@layer lism-block {
  .b--btn { /* ... */ }
}

@layer lism-custom {
  .c--siteHeader { /* ... */ }
  .c--card { /* ... */ }
  .frontHero { /* ... */ }
}
```

### Custom Class

`c--` プレフィックスで定義する **Custom Class** は、コアの定義を超えてユーザーが自由に定義できるカスタムクラスです。  
名前は `lism-custom` レイヤーと対応しており、コンポーネント・ゾーニング・ページ固有の要素など、粒度を問わず使えます。

スタイルは Property Class での指定を中心に組み立てるのが基本方針で、CSSを書かずに「何のパーツか」を示す名前付けとしてだけ使っても構いません。Property Class では対応しきれない複雑なスタイルをCSSに書く場合は、`@layer lism-custom` に定義します。

```css
@layer lism-custom {
  .c--card { /* ... */ }
  .c--pricing { /* ... */ }
}
```

`c--` クラスは、[Block Class](#block-class) と同じ BEM 記法・併用ルールで BEM 構造（Block / Modifier / Element）を持つことができます。

|分類|形式|例|
|---|---|---|
|Block<br /><small>本体クラス</small>|`c--{name}`|`c--button`,<br />`c--card`|
|Modifier<br /><small>バリエーション</small>|`c--{name}--{modifier}`|`c--button--outline`|
|Element<br /><small>子要素</small>|`c--{name}_{element}`|`c--card_header`,<br />`c--card_body`|

### プレフィックスなしのクラスで守ること

- 一般名詞ひとつ（`.hero`, `.card` 等）の命名は避け、ページのslug等を含む camelCase（`.frontHero`）にしてください。外部CSSとの衝突を防ぎ、名前だけでどこのものかわかるようにするためです
- CSSは `@layer lism-custom` に置いてください。レイヤーの外に書くと、Property Class で上書きできるという前提が崩れます
- 複数ページで使い始めたら `c--` へ昇格させましょう（[Block Class](#block-class) の3条件を満たすなら `b--`）


## 動的な状態管理はdata属性

Javascriptで動的に付け外しされるような状態管理には、data属性を使用します。

例: `[data-opened]`, `[data-active]`
