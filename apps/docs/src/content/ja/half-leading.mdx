Lism CSSでは、`line-height` の扱いが独特となっており、**ハーフレディングの値でline-heightを管理する**仕組みになっています。

ハーフレディングとは、`line-height`から文字サイズを除いた上下の余白部分のことです。


## 仕組み

Lism では、全要素に対し、以下のスタイルが適用されています。

```css
* {
  line-height: var(--lh, calc(1em + var(--hl) * 2));
}
```

これにより、`line-height`の値は基本的に、`--hl` というハーフレディングを指定するための変数に依存する仕組みになっており、
**どんな文字サイズのテキストに対しても同じ余白量**でレイアウトを組んでいくことが可能です。

`--lh`（unitless 比率）がセットされている場合は、そちらが優先されます（後述の `lh` プロパティで使用します）。

:::note
`line-height` はこの全要素ルールで管理されているため、素の CSS で要素に `line-height` を直接指定しても、子要素には継承されません（子要素自身も `*` ルールで再計算されるため）。行間の制御は `--hl` / `--lh` 変数（`hl` / `lh` プロパティ）経由で行ってください。
:::


## トークン

`--hl` にセットする値として `--hl--xs`〜`--hl--xl` のトークンを用意しています。一覧とプレビューは [タイポグラフィトークン](/docs/tokens/typography/#hl-half-leading) を参照してください。

## `lh`（line-height）

行間は通常 `hl`（half-leading）プロパティ（`-hl:*` クラス、`<Lism>` 系コンポーネントでは `hl` prop）で指定しますが、実際の `line-height`（unitless 比率）で管理したい場合のために、独立した `lh` プロパティを用意しています。

|指定|挙動|
|---|---|
|`lh="xs"` / `"s"` / `"m"` / `"l"` / `"xl"`|`--lh` に [LHトークン](/docs/tokens/typography/#lh-line-height)（`1.25`〜`2.25`）をセット|
|`lh="1"`|`--lh: 1`（行間なし）|
|`lh="1.7"` などの任意の数値|`--lh: 1.7` としてセット|

いずれも `--lh` 変数経由で出力されるため、unitless 比率が子要素にも継承され、それぞれのフォントサイズで行送りが再計算されます。

### `hl` との棲み分け

- `hl`: フォントサイズに依存しない固定量で行間を管理します。基本はこちらを使用してください。
- `lh`: フォントサイズに対する一定比率で行間を管理します。画面サイズでフォントサイズが大きく変わるグラフィカルなタイポグラフィ（ヒーローの見出しなど）で、余白感を比率のまま維持したい場合に使用します。

なお、`lh` を指定した要素の子孫では継承された `--lh` が優先されるため、`hl`（`--hl`）の指定は効かなくなる点に注意してください。


## ハーフレディング管理のメリット

line-heightを`1.6`などの一般的な値でセットした場合、フォントサイズが大きくなるにつれて、line-heightの値も大きくなってしまいます。

ベースサイズ付近のテキストであればそれでいいのですが、見出しなどになるとこれでは大きすぎて読みづらいという問題が発生してきます。

行間のハーフレディングを、固定値で管理することで、フォントサイズが大きくなってもテキスト間の距離が一定に保たれます。
